## Frontend Development

Već jako dugo frontend je sve samo ne *"HTML, CSS, JavaScript"*. To je kompleksan sistem razvoja softvera, od dizajniranja i programiranja koda, implementiranja biznis logike, optimizacije koda i performansi, pa sve do realizacije dizajna i pristupačnosti.

Drugim rečima, **frontend je kao i svaka druga grana razvoja softvera**. Ima svoje procedure, zahteve i potrebe.

## Framework Agnosticizam

Pre samo par godina React developer nikada ne bi mogao da bude primljen na poziciju Angular developera. Zašto? Jer je ranije poznavanje određene tehnologije oblikovalo vašu karijeru, zato što je kriva učenja i razumevanja tehnologije bila izuzetno velika, da biste bili u stanju efektivno raditi i razvijati.

Danas je to potpuno drugačije:
- Poznavanje sintakse vam **ne znači ništa**.
- Poznavanje i znanje su i te kako važni.
- Ali je definitivno **najvažnije** da inženjer ima celu sliku i poznaje web arhitekturu i obrasce nevezano za neki tamo framework (Vue, React ili Angular).

Znati kako kompletan Frontend funkcioniše, potom uz pomoć AI-a uraditi isti zadatak nevezano za tehnologiju, jeste ono što će biti potrebno da svaki FE developer obavlja, kako bi bio upotrebljiv u eri AI razvoja.

### Zašto?

Jasno vam je da AI drastično menja dinamiku isporučivanja softvera, samim tim i diže očekivanja menadžmenta i product owner-a.

Ako sutra PM/CEO, nebitno ko, iz x-y razloga odluči da vaš frontend softver treba da se prepiše sa **Angular**-a u **Vue** ili još gore... **React** *(nemam ništa ni protiv jednog ni drugog)*.

### Problem zavisnosti

Veliki problem bi nastao ako ti ne znaš adekvatno koristiti `useEffect`, ili ne umeš upravljati stanjem već samo "bloatuješ" kod sa `useState`... :-)

Ili ti je React "tesan" pa tvoj projekat postane "funkcionalni haos", zbog odsutnosti pravila projektne strukture...  

### Rešenje

Nije potrebno da razmrsuješ React JSX špagete, niti da mozgaš koje pakete da instaliraš za skoro sve:

**Uz pomoć AI-a možeš efikasno obaviti isti task nevezano za tehnologiju, uz pretpostavku da razumeš koncepte i obrasce koji su bitni na frontendu.**

> *Render i state* su isti koncepti u svakom framework-u...

Ako znaš i umeš da barataš time u npr. Angular-u, isto ćeš to moći u React-u, jer će ti kod pisati AI kojim ćeš ti orkestrirati i voditi kroz ceo proces.
Dok će tvoji nadređeni biti srećni i zadovoljni što si uspešno migrirao aplikaciju sa Angular-a na React *(što možda i nije baš pametno ako mene pitate*).

Jer na kraju dana, kada se tvoj kod kompajlira i pokrene u browser-u, razlika između ovog source koda u Angular-u:

```typescript
import { Component, signal } from '@angular/core';

@Component({
  selector: 'app-counter',
  standalone: true,
  template: `
    <div class="counter-card">
      <h3>Angular Counter</h3>
      <p>Trenutna vrednost: {{ count() }}</p>
      <button (click)="decrement()">Smanji</button>
      <button (click)="increment()">Povećaj</button>
    </div>
  `,
  styles: [`
    .counter-card { padding: 16px; border: 1px solid #dddfd4; border-radius: 8px; }
    button { margin-right: 8px; padding: 6px 12px; cursor: pointer; }
  `]
})
export class CounterComponent {
  count = signal(0);

  increment() {
    this.count.update(value => value + 1);
  }

  decrement() {
    this.count.update(value => value - 1);
  }
}
```

...i ovog source koda u React-u:

```jsx
import React, { useState } from 'react';

export function CounterComponent() {
  const [count, setCount] = useState(0);

  return (
    <div className="counter-card" style={{ padding: '16px', border: '1px solid #dddfd4', borderRadius: '8px' }}>
      <h3>React Counter</h3>
      <p>Trenutna vrednost: {count}</p>
      <button onClick={() => setCount(count - 1)} style={{ marginRight: '8px', padding: '6px 12px', cursor: 'pointer' }}>
        Smanji
      </button>
      <button onClick={() => setCount(count + 1)} style={{ padding: '6px 12px', cursor: 'pointer' }}>
        Povećaj
      </button>
    </div>
  );
}
```

**Ne postoji...**

Tako da vam AI može otvoriti vidike što se tiče tehnologija, i omogućiti vam da nesmetano programirate frontend aplikacije nezavisno od tool-a, što je u industriji jako *"hot"* fazon poznat pod nazivom **"Framework Agnostic"**.

## Agentic Razvoj i AI Orkestracija

Razvoj u agentic okruženju postao je naša svakodnevnica. Orkestriramo i "promptujemo" agentima da izvršavaju najrazličitije zadatke — od pisanja testova do arhitektonskih refaktoring-a.

### Uticaj na kvalitet koda
Iako agenti efikasno izvršavaju instrukcije čak i kada su promptovi nedovoljno precizni, ključna poluga kvaliteta leži u našem umeću upravljanja njima:
- **Kontekstualna pravila:** Definisanje jasnih pravila i konvencija projekta (npr. kroz `CLAUDE.MD` ili sistemske instrukcije).
- **Strukturirani Skill-ovi:** Korišćenje modularnih veština i referenci za vođenje AI-ja u pravom smeru.
- **Strategija promptovanja:** Odabir pravog pristupa — od brzih *One-Shot* promptova za jednostavne izmene, do dubokog planiranja i bogaćenja konteksta za kompleksne sisteme.
